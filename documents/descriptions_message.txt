# Описание внутренних сообщений системы

## Описание сообщений сообщений типа list_instances

Данное сообщение описывает количество всех исполнителей.
Формируется модулем обращения к базе данных при поступлении запроса либо конвертером при обновлении базы данных.
Примечание: модуль обращения к базе данных формирует список доступных исполнителей задач.

Каждому исполнителю назначается определенное количество задач. В результате формируется полноценный список задач на исполнение.

Описание исполнителя задач.
В базе на каждого исполнителя храниться информация:
- идентификатор исполнителя;
- имя исполнителя;
- регион обработки задач исполнителем;
- байт компетентности;
- метка исполнителя по статусу работ:
	- статус исполнителя не известен;
        - исполнитель недоступен;
        - исполнитель выполняет задачу;
        - исполнитель не имеет назначенных задач;
- тип перемещения исполнителя задач:
        - тип неизвестен;
        - пешеход;
        - велосипед;
        - мотоцикл;
        - автомобиль;
        - общественный транспорт;
- текущее положение исполнителя.

## Описание сообщений сообщений типа user_request

Данный класс является некоторым представлением запросов, которые отправляет пользователь.
К таким запросам относятся:
- регистрация новых исполнителей задач;
- новые заявки (массив заявок);
- срочная заявка (например, авария);
- отмена заявки;
- получение состояния текущего списка исполнителей задач;
- получение данных о текущих выполняемых задачах;
- получение данных о не назначенных задачах;
- и тд.

Контейнер регистрирует сообщение типа user_request который содержит:
- тип запроса:
	- тип  не известен;
	- обновить базу данных;
		- тип неизвестен;
		- добавить новых исполнителей задач;
		- удалить исполнительных задач;
		- заблокировать исполнителей задач;
	- обработать данные (сформировать расписание);
		-тип неизвестен;
		- распределить задачи между исполнителями;
		- перераспределить задачи, срочная заявка;
		- перераспределить задачи, заявка отменена;
	- тип запроса: обработать данные (сформировать расписание);
		- тип неизвестен;
		- распределить задачи между исполнителями;
		- перераспределить задачи, срочная заявка;
		- перераспределить задачи, заявка отменена;
	- получить информацию из базы данных:
		- тип неизвестен;
		- получение всех свободных исполнителей задач;
		- получение всех занятых исполнителей задач;
		- получение всех не назнченных задач;
		- получение всех задач в обработке;
		- получение всех выполненных задач;
		- текущее положение всех исполнителей.

## Описание сообщений сообщений типа list_tasks

Данное сообщение формируется либо модулем обращения к базе данных при поступлении запросов на получение соответствующей информации либо модулем конвертации данных в случае поступления новых заявок на обработку.
Содержит информацию о всех задачах, которые:
- выполнены (из базы данных);
- не выполнены (из базы данных);
- которые требуют выполнения (конвертация, поступает из frontend);
- назначены (из базы данных);
- и т.д.

Контейнер регистрирует сообщение типа list_tasks который содержит:
- список задач на исполнение;
- описание выполняемой задачи:
        - уникальный идентификатор задачи на исоплнение;
        - тип задачи на выполнение;
        - положение задачи на карте;
        - временное окно выполнения задачи;
        - регион исполняемой задачи;
- метки задач (с приоритетами):
        - тип задачи неизвестен;
        - тип задачи "авария" (приоритет наивысший);
        - тип задачи "подключение" (приоритет средний);
        - тип задачи "локальная заявка" (ремонт/дозаказ) (наименьший приоритет).

## Описание сообщений сообщений типа time_table

Данное сообщение содержит информацию о том, сколько времени будет затрачено от точки A до точки B в виде таблицы
Данная таблица может корректироваться в соответствие с текущей дорожной ситуацией
Важно! При больших объемах данных (несколько тысяч задач) хранение данной таблицы может привести к полному заполнению ОЗУ
В этом случае имеет смысл обращаться к временной таблице через запросы в базу данных

Контейнер регистрирует сообщение типа time_table содержащий таблицу

# Описание функциональных компонент системы

## Описание компоненты request_listener

Модуль получения запросов от пользователя
- Данный модуль только принимает запросы и формирует соответствующее сообщение для остальных модулей системы.
- По сути это входная точка для обработки данных.

## Описание компоненты converter

Данный модуль принимает входные запросы и конвертирует в нужный для обработки формат:
- список задач на обработку;
- временная матрица путей.

## Описание компоненты database_query

Модуль формирует запросы в базу данных в зависимости от пользовательского запроса и в зависимости от запроса:
- формирует описание всех исполнителей задач;
- формирует описание доступных исполнителей задач;
- формирует описание всех задач на обработку;
- формирует описание всех выполненных задач;
- формриует описание всех невыполненных задач;
- формирует описание всех задач, выполняемых на текущий момент времени;
- и т.д.

## Описание компоненты task_distribution

Основной модуль!
При распределении задач учитывает следующие особенности:
- стартовое положение всех исполнителей задач;
- временные окна;
- типы задач;
- навыки исполнителей;
В случае поступления каких-либо задач высшего приоритета (например, авария) может переназначить выполнение задач в зависимости от:
- текущего положения исполнителя;
- текущего состояния работ.

## Описание компоненты vroom_problem_solver

Модуль решения задачи о назначениях
Решение выполняется посредством использования библиотеки VROOM
Данный модуль учитывает:
- тип транспортного средства, используемого каждым исполнителем задач;
- компетенции исполнителей задач;
- временные окна исполнения задач;
- стартовые позиции всех исполнителей задач (мультидепо);
- длительность выполнения задач.

Примечание. Логика модуля task_distribution и модуля vroom_problem_solver тесно связана: task_distribution управляет общей логикой и приоритетами, а модуль vroom_problem_solver выполняет непосредственную оптимизацию маршрутов и назначений.
